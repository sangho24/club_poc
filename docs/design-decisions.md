# 디자인 결정 기록

`src/theme.ts` 는 값과 그 값을 고른 짧은 이유만 갖는다. 왜 그 방향으로 갔는지의 서사는 여기 있다.
토큰 파일에 문단이 쌓이면 코드로 읽히지 않는다.

읽는 순서: 아래로 갈수록 최근이다.

---

## 2026-08-11 · 다크 네이비에서 흰 바탕으로 뒤집었다

처음에는 다크 네이비 위에 오렌지가 발광하는 톤으로 잡았다. 구단 앱의 성격(팬덤 미디어)에는
맞았지만 **읽는 화면으로는 실패했다.**

심화 스탯·확률 근거처럼 글자가 많은 화면에서 어두운 면은 대비를 벌기 어렵다. 그리고 오렌지가
넓게 쓰이면 그 자체가 소음이 되어 정작 봐야 할 수치가 묻힌다.

**그래서 흰 바탕이 기본이고, 구단 색은 보조다.** 기존 KBO 앱(`kbo_poc`)이 확립한 iOS 그룹 리스트
문법을 그대로 따른다 - `#F2F2F7` 배경 + 흰 카드 + 작은 회색 섹션 머리글, 모서리 24·14·999, 평평한 카드.

구단 앱임을 드러내는 것은 **면적이 아니라 자리다.** 오렌지는 브랜드 마크·선택 상태·핵심 수치·
게이지에만 놓고, 본문과 카드는 무채색이 가져간다. 같은 규칙을 KBO 앱은 네이비로, 이 앱은
오렌지로 쓰는 것이라 두 앱은 여전히 한눈에 구분된다.

### 딸려 나온 규칙 둘

**섹션 머리글은 작은 회색이다.** 초판은 18pt 굵은 검정이었는데, 그러면 화면을 내릴 때마다 굵은
제목이 연달아 나와 **화면 전체가 제목 대결**이 된다. 그 균일한 반복이 곧 "만들다 만 화면"처럼
보이는 원인이다. 머리글이 물러나야 흰 카드가 시각 단위로 읽힌다.

**목록의 항목마다 카드를 띄우지 않는다.** 같은 라운드·같은 패딩의 흰 상자가 끝없이 반복되면
어디가 묶음이고 어디가 낱개인지 구분이 사라진다. 묶이는 것은 카드 하나 안의 행으로 넣는다.

## 2026-08-25 · 토큰 레이어 재설계 (S2)

`HeroUI` 71개 컴포넌트 실측과 `WWiT` 캡처 101장 판독을 근거로 축을 다시 세웠다.
갭 분석은 [`design-gap.md`](./design-gap.md) 에 있다.

### 1. 틴트를 파생 함수로 바꿨다 — 그리고 15% 가 아니라 10% 다

`brandSoft` `liveSoft` `winSoft` `warnSoft` 네 개가 각각 하드코딩되어 있었다.
역산해 보니 **원저자는 이미 사실상 같은 규칙을 쓰고 있었다.**

| 토큰 | 값 | 역산한 알파 |
|---|---|---|
| `brandSoft` | `#FFEDE5` | 약 10.2% |
| `winSoft` | `#E8F3ED` | 약 10% |
| `liveSoft` | `#FBE9ED` | 약 9% |
| `warnSoft` | `#F6EEDC` | **7~15% (채널마다 제각각)** |

규칙은 있었지만 코드에 적혀 있지 않았다. 그래서 색을 하나 더 만들 때마다 손으로 틴트를
만들어야 했고, `warnSoft` 처럼 규칙에서 벗어난 값이 섞여도 아무도 몰랐다.

**HeroUI 를 그대로 따르지 않은 이유.** HeroUI 의 `danger-soft` 를 실측하니 `색상 / 0.15` 였다.
그 값을 우리 색에 적용하면 위에 얹는 글자 대비가 이렇게 된다.

```
알파   brand  live   win    warn   최저    AA(4.5)
15%    4.33   4.27   4.32   4.39   4.27    ❌
13%    4.46   4.43   4.46   4.51   4.43    ❌
11%    4.58   4.60   4.56   4.63   4.56    ✅
10%    4.62   4.66   4.66   4.71   4.62    ✅   ← 채택
```

15% 를 쓰면 **접근성이 후퇴한다.** 10% 는 기존 하드코딩 값과 같은 수준을 유지하면서
네 개를 규칙 하나로 대체하고, 어긋나 있던 `warnSoft` 를 교정한다.

**남는 제약: 알파는 뒤에 무엇이 있는지를 탄다.** 위 수치는 전부 흰 카드 기준이다.
회색 지면(`colors.bg`) 위에 얹으면 3.9:1 로 떨어진다.
**틴트 배지는 카드 안에만 둔다** - 이 규칙을 어기면 대비가 조용히 무너진다.

### 2. 항목을 구분만 하는 색을 신설했다

기존 색은 전부 의미를 갖는다 - 브랜드·진행중·승·경고·신뢰도. 구종 비율이나 타구 방향처럼
**의미는 없고 서로 구별만 되면 되는** 자리에 쓸 색이 하나도 없었다.
승을 뜻하는 초록으로 '슬라이더'를 칠할 수는 없다.

```
라이트  #0A78D4  #00A08C  #7A45E0  #D1257E  #3E9B22
다크    #2E86DB  #0FA88A  #8B60E2  #DB4A8F  #4FAE33
기타    #98A0AB
```

**오렌지 인접 hue 를 통째로 비웠다.** 구단 색이 오렌지라 카테고리에 오렌지가 섞이면
선택 상태와 혼동된다.

**눈으로 고르지 않았다.** OKLab 기준 6개 검사(명도 밴드·채도 하한·색각이상 분리·정상시각 하한·
지면 대비)를 돌렸다. 첫 후보는 탈락했다.

```
[FAIL] Chroma floor         #14897A(0.098) #6E7581(0.02) — 회색으로 읽힘
[FAIL] Normal-vision floor  #14897A↔#1E7FBF ΔE 12.2 — 색각 이상이 아니어도 구분 어려움
```

hue 를 벌리고 회색을 슬롯에서 빼서 통과시켰다. 회색은 카테고리가 아니라 '기타' 전용이다.

**다섯에서 멈춘다.** 여섯 번째 항목은 색을 새로 만드는 게 아니라 `other` 로 접는다.
색을 늘리는 순간 위 검사가 깨진다.

### 3. 굵기를 다섯 단계에서 세 단계로 줄였다

`400 · 500 · 600 · 700 · 800` 을 쓰고 있었다. 단계가 다섯이면 무엇이 더 중요한지 눈이
판단하지 못한다. **500 과 800 을 버렸다.**

| 토큰 | 지금 → 제안 | 이유 |
|---|---|---|
| `metric` | 800 → 700 | 수치는 크기로 이미 강하다. 굵기까지 최대면 소리를 지른다 |
| `cardTitle` | 700 → 600 | 화면에서 가장 굵은 자리를 수치에 넘긴다 |
| `caption` | 500 → 400 | 500 은 400 과 구분되지 않으면서 단계만 늘렸다 |

2026-08-11 에 머리글을 작은 회색으로 물린 것과 같은 문제였다. 머리글은 물러났는데
**카드 안쪽에서 같은 제목 대결이 다시 벌어지고 있었다.**

HeroUI 는 UI 전반이 500 하나인데, 한글은 500 이 얇게 뭉개져 그대로 쓸 수 없어 400/600/700 으로 갔다.

### 4. 컨트롤에 크기 축을 세우고 primary 버튼을 만들었다

버튼이 `ExternalButton`(앱 밖으로 나가는 링크)과 `SecondaryButton`(회색 보조) 둘뿐이었다.
**가장 중요한 행동을 담을 버튼이 없어서** 그 자리를 카드 전체 터치가 대신 메우고 있었다.
카드를 누르면 뭔가 일어나지만 무엇이 일어나는지는 눌러 봐야 안다.

```
sm 36   md 44   lg 52
```

**HeroUI 는 32/36/40 인데 따르지 않았다.** 그건 마우스로 누르는 웹 기준이다.
손가락 최소 터치는 44 이고 `spacing.touchMin` 에 이미 그렇게 적혀 있었다.
구조는 HeroUI 를 따르되 수치는 모바일로 옮긴 자리다.

### 5. 게이지가 새는 구멍을 막았다

`Gauge` 의 `tone` 이 `string` 이었다. 화면이 원시 값을 직접 넘기고 있었다.

```ts
// PlayersScreen.tsx:306, 377
<Gauge position={pt.usage} tone={colors.neutralFill} />
<Gauge position={pos} markerAt={midPos} tone={above ? colors.brand : colors.neutralFill} />
```

토큰 체계 밖으로 새는 구멍이라, 새 토큰을 만들어도 화면이 그냥 우회한다.
`gaugeFill` 맵과 `GaugeTone` union 으로 막았다. 벗어나면 컴파일이 멈춘다.

### 6. 상태를 정의했다

`disabled` 와 `loading` 을 받는 컴포넌트가 하나도 없었다. 눌림만 있고
**'지금은 누를 수 없다'와 '기다리는 중이다'를 말할 방법이 없었다.**

`disabled` 는 0.38 이다. 0.5 는 아직 눌릴 것처럼 보인다.

## 2026-08-25 · 컴포넌트 적용 (S3)

### 7. 굵기 누수 28곳 - S2 가 눈에 띄지 않았던 이유

`typography` 토큰의 굵기를 세 단계로 줄였는데 화면이 거의 그대로였다. 세어 보니
**토큰을 거치지 않고 `fontWeight` 를 직접 쓰는 자리가 28곳**이었다.

```
전  700×24  800×17  600×17  500×11  400×2
후  700×41  600×17  400×13
```

`Gauge` 의 `tone: string` 과 정확히 같은 종류의 누수다. 토큰을 고쳐도 화면이 우회한다.
**토큰 레이어를 바꾸는 작업은 반드시 사용처 전수 조사를 동반해야 한다.**

### 8. 봉인이 실제로 잡았다

`GaugeTone` union 을 넣자 컴파일러가 두 곳을 세웠다.

```
PlayersScreen.tsx(306,46): Type 'string' is not assignable to type
  '"brand" | "warn" | "neutral" | "good" | "bad" | undefined'
PlayersScreen.tsx(377,49): ...
```

306 행은 **구종 사용률**이었다. 직구·슬라이더·커브는 의미가 아니라 구별이므로
카테고리 팔레트가 들어갈 자리다. 전에는 전부 같은 회색이라 막대만 봐서는 어느 줄이
어느 구종인지 알 수 없어 이름을 매번 다시 읽어야 했다.

다만 봉인을 뚫지 않았다. 화면은 색이 아니라 **슬롯 번호만** 넘긴다.

```tsx
<Gauge position={pt.usage} category={i} />
```

`categoryColor(i)` 가 5개를 넘으면 `other` 로 접으므로 "다섯에서 멈춘다"는 규칙이
코드에서 저절로 지켜진다.

### 9. 구간 게이지가 잘못된 신호를 하나 교정했다

377 행(심화 지표 게이지)을 `RangeGauge` 로 바꿨더니 값이 달라졌다.

```
전   wRC+ 오렌지    wOBA 오렌지    BABIP 오렌지     ← 셋 다 "평균 초과"
후   wRC+ 상위      wOBA 상위      BABIP 평균권
```

BABIP .320 은 리그 평균 .310 보다 높지만 **정상 범위 안**이다. 예전 게이지는 평균을
넘었다는 이유만으로 wRC+ 126 과 똑같은 구단 색을 칠했는데, 실제로는 노이즈 수준
차이였다. 구간이 그것을 구분한다.

밴드 경계는 기존 `low·mid·high` 세 지점의 중간이다 - **없던 리그 기준을 지어내지 않았다.**
`gaugePosition` 이 방향을 이미 정규화해 둬서(1 이 언제나 좋은 쪽 끝, ERA 처럼 낮을수록
좋은 지표도 마찬가지) 상위·하위로 읽을 수 있다.

### 10. 부팅 빈 화면

`boot === 'loading'` 이 `<SafeAreaView />` 하나만 반환하고 있었다. 빈 화면은 '오는 중'이
아니라 '아무것도 없음'으로 읽혀서 앱이 죽은 것처럼 보인다. 홈 화면과 같은 리듬의
자리표시자를 세웠다.

⚠ 웹에서는 저장소 읽기가 마이크로태스크 하나라 **사실상 보이지 않는다.**
타입체크와 코드로만 확인했고 실기기 AsyncStorage 에서 잠깐 나타날 것이다.

## 아직 하지 않은 것

**다크모드는 열어만 두고 켜지 않았다.** `categorical.dark` 는 들어갔지만 나머지 색은
라이트 전용이다. 토큰 구조가 다크를 받을 수 있게 되었다는 뜻이지 지금 동작한다는 뜻이 아니다.

**`Button` 을 쓰는 화면이 아직 없다.** 컴포넌트는 만들었고 `SecondaryButton` 이 내부적으로
쓰지만, `primary` 가 필요한 자리를 화면별로 정하는 것은 S4 다.
"이 화면의 주된 행동이 무엇인가"는 디자인 판단이라 기계적으로 넣을 수 없다.

**남은 신설 컴포넌트**: 해석 배너(P6 - 사실과 해석이 같은 옷을 입고 있다) ·
행 끝 판정 텍스트 · 범례 행 · 근거 항목이 순차로 켜지는 로딩.
