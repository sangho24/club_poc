# 디자인 갭 분석 (S1)

레퍼런스 두 개를 실측해 현재 앱과 대조한 결과다. S2(토큰 레이어 재설계)의 근거가 된다.

- **HeroUI** (heroui.com) - 웹 컴포넌트 라이브러리. **체계**를 가져온다 (스케일·variant 축·상태 정의)
- **WWiT** (wwit.design) - 국내 모바일 앱 UI 아카이브. **한국 사용자가 학습한 문법**의 증거를 가져온다

HeroUI 는 Tailwind 기반 웹 전용이라 RN 에 설치할 수 없다. 값이 아니라 **구조**만 이식한다.

---

## 1. 구조 결손 - 축이 없다

HeroUI 는 모든 컴포넌트가 `variant × size × color` 3축이다. 현재 앱에는 **size 축이 하나도 없다.**
버튼도 칩도 배지도 크기가 하나뿐이다.

| 축 | HeroUI (버튼 실측) | 현재 club_poc |
|---|---|---|
| variant | primary / secondary / tertiary / outline / ghost / danger / danger-soft (7) | ExternalButton, SecondaryButton (2) |
| size | sm h32·px12 / md h36·px16 / lg h40·px16 | 없음 |
| radius | 24 통일 (md 에선 사실상 pill) | card 24 / tile 14 / chip 999 |
| font-weight | **500 하나** | 600 / 700 / 800 혼용 |
| border | 0.8px hairline | 1px |
| shadow | none | 평평 (일치) |
| soft 배경 | `색상 / 0.15` **알파 공식** | `brandSoft: '#FFEDE5'` 하드코딩 |

### 1-1. primary 버튼이 없다

버튼이 `ExternalButton`(앱 밖으로 나가는 링크)과 `SecondaryButton`(회색 보조) 둘뿐이다.
**화면에서 가장 중요한 행동을 담을 버튼이 없어서** 그 자리를 카드 전체 터치나 외부 링크가 대신 메우고 있다.

### 1-2. `Gauge` 의 `tone` 이 자유 문자열이다

```ts
tone?: string;   // 아무 색이나 들어갈 수 있다
```

토큰 체계 밖으로 새는 구멍이다. 여기를 semantic 으로 막지 않으면 S2 에서 새 토큰을 만들어도
화면에서 우회된다. HeroUI 라면 `color: 'primary' | 'success' | 'warning'` 이다.

### 1-3. 상태가 없다

`disabled` · `loading` 을 받는 컴포넌트가 하나도 없다. `pressHighlight = {opacity: 0.6}` 하나로
모든 눌림을 처리한다. **Skeleton 도 Toast 도 없어서 로딩과 실패를 화면에 표현할 방법 자체가 없다.**

### 1-4. HeroUI 71 개 대비 결손 컴포넌트

Skeleton · Toast · Meter · ProgressCircle · Accordion(Disclosure) · Avatar · Input/SearchField ·
Tooltip/Popover · ButtonGroup

## 2. WWiT 실측 - 국내 앱이 실제로 쓰는 문법

`/component/chart` 63장, `/pattern/loading` 38장을 받아 판독했다.
차트는 **금융·건강 앱이 압도적**이다(뱅크샐러드 11, 네이버페이 10, 신한플레이 8).
다차원 수치 지표라는 문제 구조가 야구 스탯과 같아 그대로 참고가 된다.

### 2-1. 분절 게이지 - 정상 범위를 트랙에 그린다 (알라미)

```
수면 시간  6시간                                      주의
수면시간이 부족해요
  ▬▬▬▬▬▬▬▬  ─────────  ─────────
   짧음      [7~9시간 권장]      너무 김
```

트랙을 3구간으로 나누고, **현재 값이 속한 구간만 색이 찬다.** 권장 구간에는 라벨 칩이 붙는다.

**이것이 이번 분석에서 가장 쓸모 있는 발견이다.** 심화 지표는 "정상 범위 안인지 밖인지"가 곧
정보다. BABIP .340 을 막대 길이로만 보여주면 아무 말도 못 하지만, 리그 평균 구간을 함께 그리면
"운이 좋았을 가능성"이 그림만으로 읽힌다.

현재 `Gauge` 의 `markerAt`(평균 눈금 한 점)보다 훨씬 강한 표현이다.
`theme.ts` 에 `trustHigh/trustMid/trustLow` 색이 이미 있는데 **그 색을 쓸 컴포넌트가 없다.**

### 2-2. 범례가 곧 탭 가능한 데이터 행이다 (뱅크샐러드)

```
     (도넛 차트, 최대 조각에만 흰 버블로 51% 콜아웃)

  ● 주거/통신 51%              413,380원  ›
  ● 경조사   16%              128,600원  ›
  ● 생활     15%              117,352원  ›
```

범례가 라벨이 아니라 **행 자체**다. 차트와 리스트가 한 컴포넌트다.
퍼센트는 라벨 옆 회색 작은 글씨로 두어 값(금액)과 위계를 나눈다.
**강조는 한 개만** - 가장 큰 조각에만 콜아웃을 붙이고 나머지는 색으로만 구분한다.

### 2-3. 카테고리 색 스케일이 없다 (새로 발견한 결손)

뱅크샐러드는 청록 → 파랑 → 남보라 → 보라 → 분홍 → 회색(미분류) 으로 **hue 를 회전**시킨다.
크기순으로 배열되고 색이 연속적이다.

현재 `theme.ts` 에는 `brand / live / win / warn / trust*` 같은 **semantic 색만** 있고
"여러 항목을 서로 구분하는" 색 세트가 없다. 구종 비율·타구 방향·이닝별 득점을 그리려면 반드시 필요하다.

### 2-4. 분포를 막대가 아니라 크기 다른 원으로 (필라이즈)

```
   ·      ●      ·      ●      ·
  0%   66.7%    0%   33.3%    0%
```

값이 클수록 원이 커진다. 5단계 척도의 분포를 한 줄로 보여준다.
Y축을 숫자가 아니라 **아이콘(표정)** 으로 둔 것도 같은 맥락이다 - 척도가 정성적일 때는
숫자보다 강하다.

### 2-5. 판정을 배지가 아니라 행 끝 색 글자로 (알라미)

```
수면 시간  6시간                                      주의   (주황)
수면 효율  94%                                        좋음   (초록)
```

테두리도 배경도 없이 색 글자만. 현재 `Badge` 는 카드 상단에 붙는 틴트 배지인데,
행 단위 판정에는 이쪽이 훨씬 조용하다. `Badge` 주석의 "한 카드에 배지는 하나까지" 제약도 우회된다.

### 2-6. 해석 레이어를 시각적으로 표시한다 (알라미)

AI 진단 카드에 로봇 아이콘 + 보라색 제목을 붙여 **"이건 앱이 해석한 것"** 임을 드러낸다.
현재는 `RichText` 로 문장만 넣어서 사실과 해석이 같은 옷을 입고 있다.
P6 해석 레이어가 이 앱의 핵심인데 그것을 표시하는 장치가 없다.

### 2-7. 로딩 - 두 갈래 (배민 / 헤이딜러)

**배민**: 브랜드 마스코트 애니메이션을 중앙에 두고 **탭바는 그대로 유지**한다.
로딩 중에도 앱 구조가 남아 있어 "죽지 않았다"는 신호가 된다. 우리는 이글스 엠블럼을 쓸 수 있다.

**헤이딜러**: 진행률 + **항목 체크리스트가 순차적으로 켜진다.**

```
여러 곳에 있는 숨은 이력을 불러오고 있어요.
71%
  ✓ 공장 생산이력
  ✓ 정비 이력
  ✓ 명의 변경      (회색)
  ✓ 보험 이력      (회색)
🔔 완료되면 알림을 보내드릴게요.
```

확률 엔진이 여러 근거를 조합한다면 **"무엇을 근거로 계산 중인지"** 를 로딩에 노출할 수 있다.
그러면 로딩이 대기 시간이 아니라 **신뢰 형성 장치**가 된다.

### 2-8. 검증된 것 - 세그먼트 컨트롤

필라이즈·알라미 모두 **회색 트랙 + 흰 버블**이다. 현재 `Segmented` 와 동일하다.
이 판단은 유지한다.

## 3. S2 로 넘길 것

| # | 항목 | 근거 |
|---|---|---|
| 1 | 색 스케일 + 파생 공식 (`soft = 색상 × 0.15`) | HeroUI. `*Soft` 4개 하드코딩 제거, 다크모드 열림 |
| 2 | **카테고리 색 스케일 신설** | 뱅크샐러드. 현재 완전 부재 |
| 3 | font-weight 축 축소 (600~800 → 500 기준) | HeroUI. 체감이 가장 큰 한 수 |
| 4 | variant × size 2축 도입, primary 버튼 신설 | HeroUI. 현재 축 자체가 없음 |
| 5 | `Gauge.tone` 을 semantic union 으로 봉인 | 토큰 우회 구멍 |
| 6 | `disabled` · `loading` 상태 정의 | 현재 전무 |

컴포넌트 신설은 S3 로 넘긴다: 분절 게이지 · Skeleton · Toast · 해석 배너 · 행 끝 판정 텍스트 ·
범례 행 · ProgressCircle.
